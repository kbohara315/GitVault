## Target module design

Keep the runner private to `internal/backup`. Accept a context, explicit working directory, validated operation policy, and arguments generated by the engine. Capture machine-readable stdout separately from bounded diagnostics. Do not let callers pass arbitrary environment additions or shell strings. Return structured error classification and wrapped causes.

The runner owns a process and its descendants until termination/reaping. Cancellation must not leave helpers holding pipes or staging files. Maintain OS-specific adapter code only where required.

## Steps

### 1. Document and enforce operation policy

Resolve the Git executable once. Construct a deliberate environment retaining only required OS process/runtime variables. Neutralize inherited Git config injection, object-directory/alternate variables, replacement semantics, prompts, pager, editor, templates, hooks, and unauthorized protocols. Use isolated global/system configuration and controlled repositories. Review how repository-local configuration is handled: merely disabling global config does not neutralize local alternates, partial-clone behavior, or helpers.

Define distinct local-source and offline-restore policies. The former may read an explicitly supplied local source; the latter must never retrieve missing objects remotely. Do not globally enable local transport in anticipation of GitHub support.

Add `TestGitEnvironmentIsolation` and `TestGitTransportPolicy` with synthetic hostile environment/config/template fixtures. Never mutate the developer's home or Git settings.

Verify: `go test ./internal/backup -run 'TestGitEnvironmentIsolation|TestGitTransportPolicy' -count=1` exits 0; tests prove sentinel hooks/helpers do not run.

### 2. Implement bounded capture, errors, and cancellation

Add separate stdout/stderr limits, clear truncation/error behavior, deadlines, pipe-drain bounds, process-tree ownership, and reaping. Handle commands that exit while a grandchild retains a pipe. Test with a synthetic child-process helper in the Go test binary rather than OS shell scripts when possible. Qualify Unix and Windows termination semantics; unsupported platforms return explicit typed errors before write operations.

Do not silently treat killed operations as completed. Redact diagnostic output by construction and limits; no real credentials are involved in this slice.

Verify: `go test ./internal/backup -run 'TestGitCancellation|TestGitOutputLimits|TestGitDeadline' -count=1` exits 0. The cancellation fixture proves no owned writer survives return, not only that an error was returned.

### 3. Probe Git capabilities with temporary repositories

Determine installed Git/object-format support under the same isolation policy. Test supported initialization and bundle operations against the plan-001 contract. Avoid guessing minimum Git version from a homepage; record exercised capabilities. Missing Git should produce an actionable error. Required integration CI must not silently skip every Git test.

Verify: `go test ./internal/backup -run TestGitCapabilities -count=1` exits 0 on a qualified installed Git; explicit unavailable/unsupported cases pass as negative tests.

### 4. Run regression and platform gates

Verify: `go test ./...`, `go vet ./...`, `go build ./...` exit 0; `gofmt -l main.go internal` prints nothing. Run engine integration tests on Linux, macOS, and Windows before claiming their process guarantees. Record host implementation complete separately from pending native qualification on unavailable platforms; do not mark all-platform guarantees complete. Cross-compilation alone is insufficient. `go test -race ./internal/backup` is an additional gate where supported; document toolchain requirements.

## Maintenance
